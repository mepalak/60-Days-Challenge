1. The system prompt (the assistant's "brain")

This is the production system prompt sent with every Claude API call in this app. It defines role, scope, tone, question flow, and how to handle edge cases like blank answers, off-topic input, or abuse.



    
2. Why this UI fits the use case

    
    
      
  • Chip-based setup instead of a text form — first-time interviewees don't know how to describe what they need. Tappable chips (role, stage, confidence level) remove that blank-page problem and take ~20 seconds.
    • 
      
  • Chat framed as a real interview, not a generic bot — the interviewer's messages are visually distinct (navy bubble, "Interviewer" label) from soft green feedback asides, so encouragement never gets confused with the actual question being asked.
    • 
      
  • Progress bar, not a message counter — nervous first-timers want to know "how much is left," not chat mechanics.
    • 
      
  • Muted, editorial palette (navy/brass/paper) — deliberately avoids a playful/startup look, signaling "this is a real practice room," which matches the professional & polished tone requested.
    • 
      
  • Soft feedback bubbles after each answer — because the goal is reducing anxiety, not just testing. Brief encouragement + one concrete tip appears before the next question, rather than a cold pass/fail score.
    • 
    


    
3. How to extend this

    
    
      
  • Wire up the real API: replace the mockInterviewerReply() function with a call to https://api.anthropic.com/v1/messages, sending the full conversation history plus the system prompt above each turn.
    • 
      
  • Add memory: persist conversationHistory to localStorage or a backend so returning users can resume, and so the assistant can reference "last time you struggled with X."
    • 
      
  • Multi-step flow: add a resume/JD upload step before the interview starts, and feed extracted text into the system prompt as additional context so questions are tailored to the user's actual background.
    • 
      
  • Tools: add a "generate follow-up resources" tool call at the end of the session that produces a downloadable PDF of missed questions and model answers (reuse the docx/pdf skills in this environment).
    • 
      
  • Scoring: if you want a STAR-method score dial instead of qualitative feedback, have the model return structured JSON ({clarity, structure, specificity}) per answer and render it with a small SVG gauge.
