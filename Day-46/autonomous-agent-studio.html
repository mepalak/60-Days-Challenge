Architecture Overview

Planner reads the buggy code + bug report and produces a numbered fix plan (root cause, files/functions touched, edge cases). Executor turns that plan into an actual code diff/rewrite. From there the loop begins: Evaluator scores the current draft 0–100 across correctness, quality and safety and returns structured reasoning; Critic reads that score and finds concrete, line-level problems the Evaluator's number doesn't capture; Improver takes the draft + evaluation + critique and produces the next draft. Memory Manager distills one durable lesson per round so later Improver calls don't repeat past mistakes. Safety Monitor runs each round in parallel, flagging unsafe patterns (injection, unhandled input, unbounded loops) independent of the quality score. The stop-check runs after every round in strict order — plateau, then threshold, then hard cap — and whichever fires first ends the loop and hands the final draft to the Final Reviewer, who never sees the loop, only the finished artifact, and signs off in prose a human could paste into a PR description.

Extension Ideas

Real test execution
Swap the Evaluator's self-reported correctness for an actual sandboxed test run, and feed real stack traces back into the Critic.
Multi-file context
Give the Planner a repo map / retrieval tool so fixes account for callers elsewhere in the codebase, not just the pasted snippet.
Human-in-the-loop gate
Pause before Final Reviewer when Safety Monitor flags anything, requiring explicit approval before the fix is considered done.

Further Prompts for Building More Advanced Autonomous Systems

  • Add a branching Planner — "Extend this pipeline so the Planner can propose two competing fix strategies, run both through one Evaluator round in parallel, and let a Selector agent pick which one enters the Improver loop."
  • Add persistent cross-session memory — "Give the Memory Manager a way to write lessons to browser localStorage keyed by bug category, and have the Planner read that memory before proposing a plan on a new run."
  • Add a rollback agent — "If a round's score drops from the previous round, add a Rollback agent that reverts to the best-scoring draft before the next Improver call, so the loop can never regress."
  • Generalize the domain — "Refactor the agent roles and system prompts so the same loop architecture drives a marketing-copy pipeline instead of a bugfix pipeline, keeping the stop-check logic untouched."
